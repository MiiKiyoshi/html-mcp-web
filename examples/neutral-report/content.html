Since 15 September the nightly suite splits its tests across the eight runners by measured duration instead of by file name. It now finishes in 47 minutes instead of 74.

What changed

The scheduler reads each test's median duration over the last seven nightly runs. It places the longest test first, each on the runner with the least total time so far, until every test has a runner.

What stayed the same

The same eight runners run the same 2,140 tests. The order of tests within a runner, the retry rule, and the report format are unchanged.

Why it helps

The suite is finished only when its slowest runner is. Splitting by file name gave runner 1 the whole integration folder, so it ran for 74 minutes while runner 8 sat idle after 18.

All times are from the nightly runs of 15 to 21 September.

The total test time is 368 minutes both ways, since only the split changed. Runners that used to finish early now take more of the work, and the suite ends when runner 1 does, 27 minutes sooner.

Two kinds of test still fall back to the old split.

New tests

A test added this week has no recorded duration, so it is placed by file name. Until it has seven runs, we will give it the median of the other tests in its folder.

Reruns after a flaky failure

A rerun goes back to the runner that failed, which already has its full share. We will send reruns to the spare ninth runner instead.
